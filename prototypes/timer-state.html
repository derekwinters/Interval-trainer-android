This is a throwaway prototype. It is not the app and none of this code ships. It exists to let you feel the timer's state model by clicking, and to catch anything that looks fine written down but feels wrong in use.

Interval timer — does this state model feel right?

A preset is an ordered list of intervals you author. Starting a workout takes a copy of that list, adds a three-second lead-in, and runs it. This page lets you drive that model: start, pause, skip, stop, advance the clock, and watch every cue fire. The question is whether the behaviour matches what you expect at each moment — especially around pausing, skipping, and the shortest interval the editor will allow.

      Open questions this is meant to settle

      All settled, 2026-09-12. A round is a work interval, so "3 of 5" counts work intervals; better visuals later. Skipping gives a three-second lead-in rather than dropping you straight in, and whether it does becomes a setting later. The generator appends, always, with trailing recovery off by default, and nothing about it is stored.
      The minimum interval is five seconds, and that is what makes the rest simple. Three ticks always fit, with two seconds to spare. A countdown can never truncate, and a tick can never land on the instant an interval begins — which would otherwise have sounded at the same moment as that interval's own start cue, something docs/spec/cues.md forbids. Raising the minimum from three seconds to five removed that case rather than deciding it.
